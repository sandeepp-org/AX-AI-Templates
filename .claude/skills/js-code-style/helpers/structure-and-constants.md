## Structure, Control Flow, and Constants (helper for `js-code-style`)

### Function Documentation

- **Every function must have a comment** — a short (1–2 line) comment above it explaining what it does and why. No exceptions, including private helpers and arrow functions assigned to variables.
- Focus on **intent and side effects**, not line-by-line narration of obvious code.

```typescript
// Wrong — no comment
const buildMeta = (context?: string, defaultMeta?: object) => { ... };

// Right — intent is clear
// Merges defaultMeta and context into a flat metadata object for Winston.
const buildMeta = (context?: string, defaultMeta?: object) => { ... };
```

### Classes: Keep Logic Focused

Class methods may contain straightforward logic (null checks, simple transformations, wiring dependencies together). However, complex business logic, heavy calculations, or reusable data transformations should be extracted into standalone helper functions in `helpers/` and called from the class. Use judgement: if a method grows beyond ~20 lines or its logic would be useful elsewhere, extract it.

A class method is a good candidate for extraction when it:

1. Exceeds ~20 lines
2. Contains logic that is independently testable
3. Would be reused by more than one method or class

**Acceptable — simple wiring and null checks inside the class:**

```typescript
static create = async (config?: LoggerConfig): Promise<Logger> => {
  const level = config?.level ?? DEFAULT_LOG_LEVEL;
  const winstonInstance = winston.createLogger({ level });
  const logger = new Logger(winstonInstance);
  Logger.#instance = logger;
  return logger;
};
```

**Better for complex setup — extract heavy logic to helpers:**

```typescript
// Builds the Logger singleton from config; delegates complex logic to helpers.
static create = async (config?: LoggerConfig): Promise<Logger> => {
  const transportInstances = await buildTransports(config?.transports);
  const meta = buildMeta(config?.context, config?.defaultMeta);
  const winstonInstance = buildWinstonInstance({ config, meta, transportInstances });
  const logger = new Logger(winstonInstance);
  Logger.#instance = logger;
  return logger;
};
```

### No Emojis

Do not include emojis in:

- Code comments
- Log messages
- Error messages
- Console output
- Commit messages generated by the LLM
- Any text content produced during code generation

### No Nested Function Definitions

Do not define functions inside other functions. Nested function definitions create hidden coupling through closures and make the code harder to read, test, and reuse. Instead, define all functions at the module's top level and pass shared state explicitly as parameters.

### Early Returns and Guard Clauses

Use early returns freely for guard clauses and error conditions. This reduces nesting and makes the happy path clear. Multiple returns in a function are fine when each return represents a distinct, well-understood exit condition.

```typescript
// Right — guard clauses with early returns
const getUserById = async (id: string): Promise<User> => {
  if (!id) {
    throw new AppError("id is required", 400);
  }

  const user = await userRepository.findById(id);

  if (!user) {
    throw new AppError("User not found", 404);
  }

  return user;
};
```

Avoid deeply nested conditionals where an early return would make the intent clearer. The goal is readability, not a fixed return count.

### No Hardcoded Values

Do not hardcode reusable values inline. Any value used in more than one place, or any value that represents a meaningful concept (URLs, limits, timeouts, keys, status codes, config, etc.) must be extracted into a named constant.

Constants should be:

- Defined at the top of the file, or in a dedicated `constants.ts` / `config.ts` module for shared values.
- Named in `SCREAMING_SNAKE_CASE` for true constants (values that never change at runtime).
- Exported from a constants file and imported where needed, rather than duplicated.

### String Literal Unions as Constants

When a type is a union of string literals, extract the values into a frozen `as const` object and derive the union type from its values. Always compare against the constant (for example, `LogLevel.DEBUG`), never the raw string literal.
